# CLAUDE.md — MaxTech Lib

**What a conduit is.** Lib's generic framework for blocks that connect to their neighbours: cables now, later pipes and wires. One `ConduitType` per block, face modes, shapes, network membership. It is not vanilla's Conduit block (our `ConduitBlock`/`ConduitBlockEntity` share names with `net.minecraft.world.level.block.ConduitBlock`/`entity.ConduitBlockEntity`; mind imports), and it no longer means any removed pipe or bundle feature (ADR-0012). Player-facing text says "cable", never "conduit".

Lib (`maxtech_lib`, ADR-0014) holds the frameworks Storage shares with any addon and registers no player-facing content apart from the shared facade item (ADR-0014 amendment); its rules are in the root `CLAUDE.md`. Read `storage/CLAUDE.md` before changing what Storage builds on: FE buffers and transfer, the task scheduler `LevelTasks`, the conduits its cables are built on, sync, security and resource keys. Addons (Farms) build conduits on the api alone (ADR-0015, `docs/api/conduit-addon.md`): the network engine (`lib.api.network`) and `Conduits` with its hooks are api, while `ConduitBlock`, `ConduitBlockEntity` and the content builder stay internal behind `ConduitView`/`ConduitHost`; a change to Lib's conduit block reaches both Storage's cables and addon conduits, and the `conduit_api_*` GameTests use the api only. Changes to `lib/common/src/api` are breaking-change candidates: bump `lib_version` and mind Storage's `lib_version_range`. Storage imports internal Lib packages, so each Storage release pins one Lib minor (`lib_version_range` in `gradle.properties`): a Lib minor bump moves that range to the new minor in the same PR.
